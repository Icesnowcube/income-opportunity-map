# 比较与验证：仅在用户要求时启用

## 比较目的

从“存在一种模式”走向“在这个人的条件下值得研究”，不能用推荐压缩尚未完成的发散。用户只想开阔视野时，不加载成评分排名。

## 条件表

| 维度 | 要查什么 | 避免的替代说法 |
|---|---|---|
| 首笔交易 | 接触谁、交付什么、谁有付款权、决策链多久 | “很容易变现” |
| 获客依赖 | 本人粉丝、主动销售、搜索、合作方或平台派单 | “上线等自然流量” |
| 资金与资源 | 现金投入、设备、库存、资格和试错上限 | 把免费工具等同零成本 |
| 持续劳动 | 单次交付工时、售后、更新、随时响应 | “订阅就是被动收入” |
| 可重复交付 | 增加客户时需要增加什么劳动 | 只看产品能复制，不看服务负担 |
| 时间自主 | 谁决定时间、能否拒绝、暂停一周会怎样 | 仅凭不坐班判断自由 |
| 风险集中 | 单一平台、客户、合作方、设备或模型供应商 | 把多个同渠道项目当作分散风险 |
| 退出与转移 | 能否暂停、交接、授权或出售；代价是什么 | 假设任何 App 都能卖 |
| 兴趣与意愿 | 对创造和经营的意愿是否相同 | 强迫每个兴趣都赚钱 |

可以用低/中/高，但每个等级必须附带可核实原因与条件；未知就写未知。没有合理数据时不计算 87 分之类精确总分。排序必须说明权重来自用户哪项要求。

## 单位经济：先分清收入归属

通常可先写：

单笔贡献 = 自己取得的收入 − 平台/支付费用 − 履约成本 − 退款及相关损耗 − 可归属的获客成本。

期间经营结余 = 所有交易贡献之和 − 固定经营费用。

另列本人投入工时、税费适用与资本占用，不把“没有发工资给自己”当作劳动免费。代理只将佣金作为自身相关收入，不把商品总成交额当佣金收入。具体会计口径不明确时不作合规认定。

示意演算必须标“假设，非报价或预测”，注明币种、期间、单位。订阅需要观察留存、取消和持续成本；买断需要观察持续新客来源；租赁需要观察利用率与折旧；信息服务需要观察更新成本。

## 最小验证，不默认再开一个月计划

围绕一个最大未知设计行动。例如：

| 未知 | 能回答它的行为 | 还不能证明什么 |
|---|---|---|
| 是否接触得到付款人 | 通过一个具体入口找到有相关经历且愿意交流的人 | 有需求或愿意付款 |
| 是否有实际问题 | 还原最近一次发生的事件和处理方式 | 会换用你的方案 |
| 是否愿意交易 | 对明确范围、价格和交付时间作出真实付款决定 | 规模化和续费 |
| 是否重复需要 | 无提示地再次使用、再次采购或续订 | 已经盈利 |
| 是否可持续交付 | 记录重复交付、维护和获客投入 | 不劳动的收入 |

记录：候选编号、假设、具体对象与入口、行动、期望观察、反证、投入上限、复盘时间。不要以点赞、礼貌认可或下载数量代替付款和使用。涉及用户联系、发布或支付时，仍需相应授权。

## 对话衔接

需要存档时使用输出模板中的“本次进度”。保留已探索方向、已否定假设、未决问题和当前模式。不要自动写私人记忆；没有写入权限时仅在回复里给可复制摘要。
